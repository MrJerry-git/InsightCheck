# 王天一：参赛版对话式体检档案管理任务书

日期：2026-09-21。负责人：王天一。状态：待开发、待验收，不代表已完成或已通知成员。

## 1. 交付目标与职责

在现有本地智能提取功能上，实现“上传/粘贴资料 → 对话补齐与核对 → 保存历史档案 → 对话新增、更正、删除 → 更新规划”的完整后端流程。遇到缺项、歧义或冲突先向用户追问，明确后才执行；明确且通过校验的操作不反复确认。删除先确认并支持撤销。

王天一负责本任务全部后端实现：模型对话编排、结构化操作校验、会话和档案持久化、接口、迁移、规划更新及测试。不把对话理解工作遗留为“等待其他成员提供模型服务”。本轮不训练模型，复用本地 Ollama/Qwen3-VL；如修改王宏锦维护的公共分析模块，先协调文件归属。

陈子正负责全部 frontend/、人体交互、对话组件及页面接入。王天一提供接口契约、样例与可运行后端，配合联调，不自行修改前端。后端交付与前端接入分别记录，不能用接口通过代替页面闭环验收。

范围仅为现有参赛版字段及心血管、血糖与代谢、肾功能相关资料。不新增疾病预测模型、不扩大为通用医疗问诊、不改变 PREVENT 方程或现有医学规则含义。

## 2. 已有基础与产品约束

- 复用 `backend/app/services/smart_import.py`、`schemas/smart_import.py`、`api/routes/smart_import.py` 的提取能力。
- 复用 `services/prevention.py`、`schemas/prevention.py`、`api/routes/prevention.py` 的校验、评估和报告能力；先阅读 `docs/SMART_IMPORT.md` 和 `docs/COMPETITION_EDITION.md`。
- 现有系统已支持文字/图片/PDF/文字型 DOCX 提取与确认，不具备完整多轮对话档案管理。不要重做 OCR 或训练模型。
- 用户界面不保留 JSON 导入/导出、原文依据、手动录入表单、直接编辑表格或公开示例入口。后台仍使用结构化 API，内部测试可保留示例。
- 取消原文依据的前端展示，不等于删除已有服务端提取校验；原文/附件不新增长期保存。需要持久化的聊天内容、结构化草稿及保留边界在接口文档中明确。
- 用户通过对话核对整理结果；未确认的信息不得当成已确认资料。人体点亮代表相关资料已确认，不代表健康、疾病或风险。
- 详情页承载历史、长期风险和无法计算原因；器官规划页及整体规划页承载建议。整体页可从导入页直接进入，不强制用户遍历器官。
- 建议原因简要、安排时间详细、依据来源简要；规则未给确定时间时明确未定，不能由模型编造日期。

## 3. 必须完成的工作

### AI-T01：先交接口契约

新增 `docs/CONVERSATIONAL_IMPORT_CONTRACT.md`，明确端点、请求/响应、错误码、状态转换和前端调用顺序，提供成功、追问、冲突、取消、超时示例。先与陈子正确认，再分批实现。

契约至少包含：档案 ID、会话 ID、稳定记录 ID、草稿/已确认状态、档案版本、消息 ID、操作 ID、待确认动作、缺项、待追问问题、实际变更摘要、服务状态、分析是否过期、分系统可用状态。API 可使用 JSON，但这些技术字段不直接展示给用户。

### AI-T02：持久会话与草稿

支持建立/恢复会话、保存消息与待完成操作、继续上传文件或发送文字；刷新页面和重启后端后可继续。隔离不同档案，禁止把不同人的资料自动合并。档案身份不明确时追问。原始文件仍按现有边界临时处理，不将其塞入会话数据库。

### AI-T03：缺项追问与人工核对

从当前输入及已有记录判断缺项、歧义和冲突，用自然语言针对性追问；无需模型生成整张重复问卷。用户回答后更新草稿并说明变化。新识别资料在用户确认前不进入已确认历史、不点亮人体、不替换已有规划。

必填项未知时保持未知；用户明确“不知道”时说明哪些能力无法计算，允许保存不完整草稿，不循环追问。可选字段缺失不无谓阻塞已有可用能力。确认可在对话中表达，服务端记录确认所对应的草稿版本。

### AI-T04：对话驱动档案操作

支持新增另一年报告；按年份/日期/上下文定位记录；修改日期、数值、单位、已确认病史和状态；删除指定记录；取消待执行操作；撤销最近一次成功的数据修改或软删除。

多条匹配或目标不明确时先追问，禁止“默认最新一条”。日期重复、同日不同来源冲突、已有病史矛盾需解释并让用户选择处理方式，不静默覆盖。确认目标绑定稳定记录 ID，不依赖列表顺序。

单位纠正与单位换算分开处理，有歧义时询问；不能重复换算。日期、单位、范围和病史一致性使用确定性的服务端校验。

### AI-T05：受控执行与一致性

模型仅提出白名单结构化动作，不能直接执行 SQL、任意代码或工具。报告正文和上传文字只作为数据，不能覆盖系统指令或授权删除其他记录。

服务端检查动作字段、目标范围、确认状态和档案版本后，事务性写入并返回真实结果。模型回答“已修改”不能作为成功依据。重复点击/请求重试须幂等；两个页面同时修改或对过期草稿确认时返回冲突并要求重新核对，不能覆盖新版本。

删除先明确对象再确认，采用可恢复方式；撤销如遇后续修改不能覆盖新数据，应解释冲突。超时、无效模型输出和取消不得产生半完成写入。

### AI-T06：连接历史、点亮与检查规划

返回心血管、血糖与代谢、肾功能的相关已确认资料、缺项及可用能力，明确区分“有资料”与“可以计算”，供前端点亮和详情页使用。

确认新增/修改/删除后更新档案版本并把相关旧分析标记为过期；支持基于当前版本重新生成规划。旧报告保留快照，显示其版本，不冒充最新结果。仅修改未确认草稿不改变已确认报告。

提供按系统查看与整体汇总建议的稳定归属/关联字段；同一建议跨系统关联时整体结果去重，保留关联说明。复用规则结果，不让模型生成疾病概率或新医疗结论。现有评估接口要求完整输入：不完整时返回可用资料和明确缺项，不能通过补默认值强行计算。

### AI-T07：运行与降级

返回模型未就绪、处理中、识别失败、超时、重试等清晰状态，前端可直接映射为导入区提示。失败后保留已保存档案与对话进度；重试不重复新增记录。可继续查看已保存结果，不假装模型成功。不新增对外开放 Ollama 或公网部署要求。

## 4. 验收案例（全部记录结果）

1. 上传人工构造报告，缺单位和吸烟状态：AI 追问，回答后补齐；未回答不得默认“否”。
2. 用户回复“不知道”：保存草稿并明确受限能力，不反复追问、不伪造预测。
3. 对同一档案先后添加两年报告：分别保存，历史正确，不覆盖前一年；含多次检查的文件也正确拆分。
4. 两年均有血糖时说“改成 5.8”：先问记录和指标；明确日期、空腹血糖及单位后只改目标字段。
5. 同日重复上传：识别重复或询问冲突处理，不自动新增/覆盖。
6. 修改单位：区分纠正标签与换算数值，校验一致性，不发生二次换算。
7. 说“删除去年的记录”：目标明确后确认，确认前不删；删除后可撤销，取消则无修改。
8. 无效日期、越界数值、病史冲突：解释原因并保留原记录。
9. 保存后刷新/重启：档案、对话和待回答问题可恢复，不串档。
10. 模型离线、超时、非法动作或上传文字要求删除记录：不误执行、不返回虚假成功。
11. 重复提交同一动作只执行一次；旧版本确认或并发修改不会覆盖新版本。
12. 更新已确认资料：历史和系统状态同步，旧规划标记过期，新规划引用新版本；旧快照保持原样。
13. 从导入完成状态直接请求整体规划，以及从系统规划进入整体规划：结果归属正确、无重复建议；资料不足明确说明。
14. 与陈子正完成真实模型页面联调：上传 → 追问 → 回答 → 确认 → 历史详情 → 整体规划 → 修改 → 重新规划。没有直接编辑表单、JSON 按钮或原文依据展示。

业务状态、执行器、校验和错误路径写自动化测试，可模拟模型输出。另用真实本地模型跑人工构造样例，记录型号、输入、耗时、追问和实际数据库变化；不得将模拟输出称为真实模型测试，也不报告未经评测的识别准确率。
