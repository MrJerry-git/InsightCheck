# 心血管体检规划：比赛版

本次交付范围是一个完整可演示的核心闭环，不代表原先全部 2.0 功能已经完成，
也不代表临床有效性或中国人群准确性已经验证。

## 启动与展示

在按 README 安装现有 Python 和前端依赖后，双击 `start-competition.cmd`。
它执行数据库迁移、构建生产页面并打开 http://127.0.0.1:3030/competition 。
也可沿用原启动脚本，从左侧“心血管体检规划”进入。
运行时无需 R、GPU、模型 API Key 或互联网；来源链接的访问需要互联网。

比赛入口使用 3030 端口，原开发页面继续使用 3000，避免开发热更新影响现场。
关闭浏览器不代表服务停止；双击 `stop-competition.cmd` 关闭比赛脚本创建的服务。
若复用了原来已启动的后端，停止脚本会保留它；手动启动的后端在原终端按 Ctrl+C 停止。
更新代码后先停止比赛服务，再重新启动以重新构建。比赛接口经同源代理连接后端，
默认后端为 127.0.0.1:8000；自定义时在构建前设置 `INSIGHTCHECK_BACKEND_URL`。

3 分钟演示路径：

1. 点击“前期随访示例”，说明它是人工构造病例，展示三次既往指标。
2. 点击“评估并生成检查建议”，展示实际计算的 10/30 年风险与历史轨迹。
3. 展示血糖年度随访建议、建议日期、触发理由和来源链接。
4. 切换“正常随访示例”再评估，对比血糖暂不自动列为年度必查的情况。
5. 将“已确诊心血管疾病”选择为“是”，重新评估，展示拒绝不适用的风险计算。
6. 恢复适用病例，保存报告快照；刷新页面后从列表回看；导出 JSON 或打印保存 PDF。

## 已实现功能

- 手动编辑多次结构化记录；导出模板、JSON 导入及服务端一致校验。
- 明确资料来源、检查时间、病史与用药状态；拒绝缺失必填项、重复日期、
  未来日期、年龄时间矛盾、病史矛盾及未知字段。
- 胆固醇 mmol/L 与 mg/dL 转换；其他指标的单位固定显示。
- PREVENT base / HbA1c 两个模型，CVD、ASCVD、HF 三类结局。
- 10 年模型 30–79 岁，30 年模型 30–59 岁；既有 CVD、妊娠、当前症状、
  超出输入范围或过旧记录时不输出数字。365 天时效限制是平台工程策略，不是 AHA 界值。
- 描述性纵向轨迹，不将趋势当作疾病诊断或治疗因果效果。
- 独立规则模块输出未来 12 个月检查关注项、理由、日期、规则版本与证据来源。
- SQLite/PostgreSQL 兼容的报告快照持久化，服务端重新计算后保存，不信任浏览器传入分数。
- 历史回看、完整 JSON 报告导出、适合打印的报告样式。

## 推荐规则边界

血糖：已确认糖尿病前期采用年度检测原则；已确认正常且年龄至少 35 岁时以
3 年为基准安排，并提示风险改变/症状/既有医嘱需要提前；糖尿病转入既有慢病随访；
未知状态或数值与状态矛盾先补资料/复核，不能自动建议免检。
BMI 首末增加至少 2 是平台提醒阈值，不是指南给定界值。

血压：40 岁及以上或超重采用年度筛查原则；已经治疗或收缩压偏高优先讨论复测随访。
血脂：展示风险供预防讨论，不硬编码任意复查周期；肾脏：糖尿病或低 eGFR 时提示核对评估安排。
不自动开出 CT、超声或心电图套餐，不调整药物，不根据风险分数随意增加检查。

来源：
- ADA 2026 表 2.5：https://pmc.ncbi.nlm.nih.gov/articles/PMC12690183/
- USPSTF 血压：https://www.uspreventiveservicestaskforce.org/uspstf/recommendation/hypertension-in-adults-screening
- KDIGO：https://kdigo.org/guidelines/ckd-evaluation-and-management/
- AHA：https://professional.heart.org/en/guidelines-and-statements/about-prevent-calculator

以上规则尚待本地医学审核，报告统一标记“待医学审核”，没有模拟专家批准。

## 数据、模型与许可

没有训练新模型。系数来自固定版本 preventr，移植时未修改系数。
上游数值病例覆盖男女、基础/HbA1c、10/30 年、三个结局共 24 个参考值。
本机下载了 CDC NHANES 2017–2018 的 11 张公开表；聚合审计见
[NHANES_PREVENT_AUDIT.json](NHANES_PREVENT_AUDIT.json)。
该数据可以检验真实输入上的计算，但不是多年随访队列，不能证明未来疾病预测准确率。
由于没有精确体检日期，不把 NHANES 冒充历年报告导入年度计划。
页面三套病例均为人工构造；模型输出是真实计算，不是写死分数。

从 backend 目录复现公开数据审计（需要 research 依赖，首次需要网络）：

```powershell
.\.venv\Scripts\python.exe scripts/audit_nhanes_prevent.py --directory ../.runtime/nhanes
```

第三方许可和商业边界见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。
本次没有签署 AHA 官方协议，不使用官方 Logo 或声称官方授权。

## 接口

- `POST /api/v1/prevention/assess`：校验输入并评估，不保存。
- `POST /api/v1/prevention/reports`：从输入重新评估并保存不可变快照。
- `GET /api/v1/prevention/reports`：最近 100 份报告摘要。
- `GET /api/v1/prevention/reports/{id}`：回看输入、风险、规则、来源完整快照。

请求结构见后端 OpenAPI 与前端导出的资料模板。此入口独立于合成 LightGBM/DeepFM 演示，
不会把原演示模型结果用作正式心血管风险。
