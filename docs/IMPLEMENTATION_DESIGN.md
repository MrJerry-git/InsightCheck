# InsightCheck 实施设计

版本：1.0。日期：2026-09-16。状态：共同开发基线；具体疾病结局、临床阈值和数据字段通过数据审计后冻结。

## 1 目标与已确认事实

本项目实现申报书中的历年体检资料辅助推荐方法。iCan 是阶段性实践，InsightCheck 是统一代码仓库。核心研究问题是纵向信息是否改善风险预测，以及风险输出是否改善项目匹配；不以堆叠模型或增加页面作为成果。

**合作方数据目前尚未获得。** 合作意向不等于已获得数据。公开数据用于过渡开发和独立方法实验，不能被描述为合作方数据或中国体检人群验证结果。现有合成样例只能证明工程行为。

第一版面向工作人员：导入历史记录，核对单位与病灶关联，选择决策日期，生成有依据的候选方案，人工确认或修改并保存审计记录。

共同完成标准：一个可重复运行的完整流程、一组可复现实验、一套可追溯数据与规则定义，以及明确说明限制的报告。

## 2 设计决策

| 编号 | 决策 | 影响 |
| --- | --- | --- |
| D01 | 使用决策日期之前已获得的信息，为下一阶段检查提供辅助建议 | 不得使用待推荐检查的未来结果 |
| D02 | 首版只验证一个异常方向 | 肺部筛查作为公开纵向数据优先审计方向，尚未认定任务可行 |
| D03 | 工程联调、公开数据实验、合作方验证分开 | 各自保存数据版本、来源和结果，不汇总为一个有效性结论 |
| D04 | 保留 LightGBM 与 DeepFM，但模型是否用于方案由验证决定 | 不强制复杂模型胜过简单基线 |
| D05 | 首先生成一套方案与可选项目，再实现三档 | 最终保留申报书三档目标 |
| D06 | 未知信息、空规则库、模型不适用均有显式状态 | 不把未知默认为正常或安全 |
| D07 | 原始数据不直接交给 LLM 作项目决定 | 第一版使用结构化解释模板 |
| D08 | 本文定义未来实现目标，不把接口设计写成已交付功能 | 现状与计划在任务和报告中分别记录 |

## 3 范围

首版必须具备：标准 CSV 导入与校验、受检者历史展示、纵向指标计算、结构化病灶匹配与人工纠正、一个风险任务的基线实验、候选项目目录、规则执行、方案证据、人工确认记录。

后续扩展：多病种、三档约束优化、任意报告自动解析、LLM 问答、可穿戴接入和跨机构验证。第一版不训练原始 CT 识别模型，不做移动应用、微服务拆分或复杂模型管理平台。

没有风险模型时，系统仍可显示历史、趋势和明确标记的规则演示；不得制造风险概率。没有经过审核的规则时，可以演示流程，但不得输出“医学规则审核通过”。

## 4 风险预测任务如何定义

“预测风险”必须写成一个可判定对错的问题。每个任务有独立 task_id、标签版本及模型制品。

任务卡必须包含：适用人群、排除条件、索引日期、允许输入及可获得时间、预测结局、预测窗口、标签依据、最低可观察随访、删失处理、分析单位、主要指标和使用限制。

示意任务：使用截至 t0 的历史资料，预测未来 H 时间内是否出现预先定义且有记录确认的异常进展。H 和“进展”阈值不能由开发者随意给定，应结合数据字典与专业核验后冻结。“未来 12 个月”只用于理解，不是已选定的临床窗口。

| 情形 | 标签处理 |
| --- | --- |
| 窗口内有符合定义的结局 | 阳性，并保存来源与确认时间 |
| 完整达到规定观察要求且未出现结局 | 按任务定义判为阴性 |
| 没有复查、失访或观察时间不足 | 未知或删失，不直接判阴性 |
| 当次已有异常 | 只有诊断性任务可作当次目标；不得冒充未来新发风险 |
| 报告描述矛盾或病灶身份未决 | 待复核，不能强行形成进展标签 |

受检者级结局和病灶级结局分开：病灶变化不能自动当作受检者未来癌症诊断；肺癌发生也不是每一枚结节恶变的标签。若随访不足以做固定窗口分类，应缩小问题或另立生存分析任务，不能静默改变标签。

## 5 数据替代与接入

具体来源、访问条件和限制见 [公开数据选型](DATASET_PLAN.md)。采用三条互不冒充的工作线：

1. Synthea 与现有可控合成病灶样例推进工程。Synthea 不能保证提供所需结节轨迹，病灶边界测试使用单独的合成夹具。
2. NLST 公开临床子集优先审计，用来判断能否开展肺部筛查纵向方法实验；字段不足时再考虑完整数据申请。
3. 合作方数据到达后，用新适配器进入同一标准模型，重新评估人群、单位、标签和分布；不直接沿用外国人群的模型阈值。

NHANES 仅作为横断面表格流程候选，MIMIC 暂不作为首选。公开可下载不代表全部适用，也不代表允许不受限制地再分发。

每次接入先生成数据清单：来源网址、获取日期、版本、许可、文件 SHA256、表名、行数、主键、日期覆盖、缺失率、单位、可用结局、重访分布和使用限制。原始包只读保存到被 Git 忽略的数据目录，转换通过脚本重复生成。

禁止将不同数据集的不同人拼接成虚构多模态患者；也不能将横断面不同调查周期拼成同一个人的随访。

### 标准数据契约

| 对象 | 必要字段或约束 |
| --- | --- |
| 来源 | source_dataset、source_version、source_record_id、source_kind |
| 受检者 | 带来源命名空间的匿名 patient_id；人口学按决策时点计算 |
| 观测 | event_time、available_at、原始值与单位、标准值与单位、质量状态 |
| 就诊或体检 | encounter_type；不能把所有住院就诊都标为体检 |
| 影像与病灶 | 报告日期、结构化来源、部位、大小、分级、原始描述、关联状态 |
| 结局 | task_id、index_date、horizon、label、observed_at、随访截止、删失与证据 |
| 项目行为 | 项目编码、行为日期、开具或执行状态、来源；与专家评价分表 |
| 专家评价 | 病例快照、项目、适合/不适合/不确定、理由、评价者、版本 |

source_kind 区分 synthetic、public_observational、partner_observational；另设用途环境 demo/research。现有 is_demo 不足以表达全部来源语义，后续迁移须兼容，不把公开真实样本标为合成。

若公开数据只有相对随访天数，保留原始偏移与精度。不得编造精确日期；无法验证 available_at 时明确时间假设和泄漏风险。

## 6 病灶与特征

保留现有术语归一、评分和趋势模块。首次只支持结构化导入及人工核对，不假定已经具备文本自动抽取能力。

病灶关联必须支持 MATCHED、NEED_REVIEW、NEW、UNRESOLVED 等明确语义。候选竞争不能直接推断新发；检查覆盖不足不能推断消失。记录人工关联与撤销，重新计算受影响特征并保留版本。

匹配评价单独建立人工核验样本，报告错误关联、漏关联和待复核比例；没有独立轨迹真值时，只能报告工程测试和人工样例结果。

静态与纵向特征分组；时间差使用实际日期或已知偏移。未来信息、最终结局字段、索引时点尚未知的项目结果必须排除。缺失标记、测量差异、单位转换和病灶匹配质量均保留。

病灶匹配质量、数据完整度、风险概率、模型适用性是不同概念，不合并成一个 confidence 分数。首版不显示未经定义的个体风险置信区间。

## 7 风险模型与实验

基线为 Logistic 回归、随机森林、LightGBM。先统一样本、特征与划分，再比较模型。参数搜索限于开发集，固定预算与随机种子。

主实验：静态特征对比静态加纵向特征；必要时单独去除病灶特征，区分一般纵向指标和病灶信息的贡献。

按受检者隔离开发与独立测试。时间外验证单独定义：训练标签在模拟训练截止日期前已可获得，测试输入在其决策日已可获得。同一人多条样本不得跨独立划分。样本有限时采用分组交叉验证，不伪装为外部验证。

填补、编码、标准化、筛选与校准均在对应训练折内学习。测试集不得用于选择阈值、模型、特征或展示最好的一次结果。

报告 ROC-AUC、PR-AUC、F1、灵敏度、特异度、阳性率、校准图与 Brier 分数；阈值依据和适用人群一并记录。按患者聚类重采样估计指标区间；与个体风险区间区别。小样本/极少阳性时先报告不稳定性，不预设可保证的 AUC。

制品包含任务卡、特征顺序、预处理器、权重、校准器、数据清单哈希、划分清单哈希、代码提交号、依赖版本、种子及指标。数据本身和受限制品不上传 GitHub。

## 8 推荐模型与级联

历史检查行为标签仅表示被开具或执行；专家适宜性标签表示指定信息条件下的判断。规则输出只能作为规则基线或明确的弱监督来源，不作为独立医学真值。

未执行项目不自动等于负样本。训练前定义候选集、可观察窗口、负样本策略、未知状态和删失。负采样后的分数不解释为医学必要性概率。

推荐基线：年龄性别、规则排序、简单受检者项目评分模型、无风险 DeepFM、完整 DeepFM。是否增加简单树模型排序按数据量决定，不预设 DeepFM 胜出。

DeepFM 训练使用折外风险分数；为某受检者生成分数的风险模型及其预处理不能见过该受检者训练数据。采用时间模拟时还须限制风险训练结局的可获得时间。对独立测试集使用仅由开发集确定的流程。

在相同候选集、相同 K 下比较 Precision/Recall/NDCG，报告实际返回数量；候选不足 K 的分母约定必须固定并显式披露。分别报告规则处理前后结果，不能用大量过滤掩盖漏推荐。

没有真实推荐标签时，只进行合成工程测试和规则示范，不宣布推荐性能。NLST 的后续诊断行为也不能自动代表通用体检套餐的适宜性。

## 9 规则与方案

规则含来源、适用人群、有效时间、版本、审核状态、所需输入和动作。硬约束、软排序、资料不足和人工判断分别定义。任何数值临床阈值须有对应来源及专业核验，不能由实现人员凭经验填入。

流程：候选目录 → 排序或明确的规则基线 → 逐项目规则 → 组合层复核 → 方案草稿 → 人工确认。最终组合还要检查重复、必要项目覆盖、费用和相互约束。

规则缺失返回 NOT_CONFIGURED，输入不足返回 REVIEW_REQUIRED 或 INSUFFICIENT_DATA；不存在“空规则库等于医学审核通过”。不可行约束返回冲突说明，不静默删去必要项目。

首版输出必要、可选、暂缓/不适用、需复核四组。后续三档在相同必要项目和硬约束之上调整可选覆盖及预算；不机械按数量增加，不强求严格包含关系。成本来源未知时显示未知，不编造价格。

规则违规率必须同时报告评价规则覆盖率、漏掉必要项目比例和待复核比例；零项目方案不能凭零违规率获评优秀。

## 10 系统架构和待建接口

保留 Next.js、FastAPI、SQLAlchemy、Alembic 分层单体。开发可用 SQLite；多用户研究环境再按需求迁移 PostgreSQL。应用启动不自动改表，变更通过迁移。

新增编排层负责从数据库按决策时点取数据、构建快照、调用特征/风险/排序/规则、保存版本化结果；模型与特征函数保持不访问数据库的边界。

以下为拟建接口，不能当作已实现：

| 接口 | 行为 |
| --- | --- |
| POST /api/v1/imports/validate | 检查模板、字段、单位、关联键，返回逐行错误 |
| POST /api/v1/imports | 幂等导入，保存来源与导入批次 |
| GET /api/v1/patients/{id}/timeline | 读取历史与证据 |
| POST /api/v1/lesion-reviews | 确认/修改病灶关联并留痕 |
| POST /api/v1/analysis-runs | 固定患者、决策日期、任务和版本，生成分析结果 |
| POST /api/v1/plans | 从分析快照生成方案草稿 |
| POST /api/v1/plans/{id}/reviews | 医务人员确认或修改及理由 |
| GET /api/v1/analysis-runs/{id} | 查看执行状态、证据、失败或降级原因 |

所有结果保存 run_id、source_kind、task_version、feature_version、model_version、rule_version、输入快照引用、时间及执行模式。前端不能自行提供可信风险分数绕过服务端计算。已有 CRUD 不等于已具备鉴权或合法方案生成入口。

页面首版集中在导入、受检者历史、病灶复核、分析与方案四个工作流程；管理与 AI 占位页后续隐藏而非假装完成。字段缺失、模型未加载、规则缺失与服务故障分别展示。

## 11 权限与数据管理

合成开发环境可单机运行。真实数据接入前实现身份认证、按职责访问、审计、备份和恢复测试；日志不记录完整报告及直接身份字段。受限公开数据遵循各自访问约定，每位实际使用者满足要求，不能借用他人授权。

公开仓库保留代码、字段映射、下载说明和允许公开的汇总；原始数据、模型及患者级输出默认不入库。对真实或受限资料，不因使用 AI 协助开发而上传到聊天或外部模型服务。

## 12 交付阶段与验收

阶段顺序不等于等待顺序：工程与数据审计可以同时推进，但模型有效性验收不能由演示替代。

| 阶段 | 交付物 | 完成条件 |
| --- | --- | --- |
| M0 对齐 | 本设计、数据计划、仓库审查 | 能区分现有实现、待建功能和数据依赖 |
| M1 工程贯通 | 环境重建、合成导入、历史与方案演示 | 干净检出可启动；重复导入不重复；错误输入可定位 |
| M2 数据可行性 | NLST 字段与样本审计、正式任务卡 | 能构造明确标签；标明不足和申请事项；不可行则记录结论 |
| M3 风险实验 | 基线、纵向消融、制品和报告 | 划分无交叉；预处理无泄漏；独立指标可复现 |
| M4 推荐与规则 | 候选、基线、适宜性评价方案、规则集 | 标签来源分开；规则/模型不越权；不足时能降级 |
| M5 首版闭环 | 方案、复核、追溯、端到端验证 | 输入到确认可操作；失败状态可解释；修改可审计 |
| M6 扩展验证 | 三档、合作方适配、反馈及报告 | 新人群单独验证；不宣称未进行的临床验证 |

第一轮开发任务：重建环境并锁定依赖；下载并审计 Synthea 小样本；确定标准 CSV；完成校验与幂等导入；审计 NLST 公开字段；修复候选竞争/空规则语义；将静态演示与真实结果入口分开。每个任务用独立分支和明确验收推进。

## 13 测试与协作约定

有意义的测试覆盖：单位转换；时间截断；同人划分交叉；训练统计泄漏；缺失/删失标签；病灶竞争；空规则；冲突组合；制品版本不匹配；导入幂等；人工修改审计；完整操作链。模型评估不能用单元测试代替。

每次提交说明改变的行为、验证方式及未验证项。性能报告记录数据/代码版本；不为展示而挑选最佳随机种子。CI 使用合成夹具，不需要真实数据密钥。

本设计作为协作入口；旧文档提供已有实现细节，冲突应修正文档并登记，不能默默改变研究任务。新增需求先说明是否属于首版以及对标签、接口、验收的影响。

## 14 尚未冻结的决策

- NLST 公开子集实际可用的筛查轮次、结局、日期与病灶对应字段。
- 具体异常方向、结局和预测窗口；取决于数据审计。
- 专家评价资源、规则来源与标注分歧处理。
- 合作方到数日期、字段、授权范围和样本构成。
- 三档费用或资源约束；在首版单方案稳定后确定。

这些问题不会阻止环境、导入、时间契约、页面和可追溯流程开发；但必须阻止没有依据的真实效果宣称。
