## 陈子正：前端界面与体验

### 目标与顺序

把已连接后端的页面整理成清晰、一致的产品界面。先完成工作台和方案详情，确认风格后再扩展到受检者、历史记录、趋势、影像及管理页面。

1. 统一配色、字号、间距、卡片、表单、按钮、状态标签和导航。可自行确定视觉风格，优先清晰易读。
2. 重构 `frontend/components/workflow/workbench.tsx`，按档案选择、指标录入、历史展示、方案结果等职责拆成可维护组件。不同页面突出自己的主要任务，避免每页重复展示全部内容。
3. 将指标历史和病灶尺寸变化做成图表及时间线。显示日期、单位和来源；只有一条记录或缺失值时正确降级，不编造连续变化。
4. 将方案详情整理为摘要、项目清单、推荐依据、规则说明和证据导出，保留已有操作。
5. 补充加载中、空数据、请求失败、保存成功反馈；照顾键盘操作和窄屏布局，减少重复提交。

### 修改范围与协作

主要负责 `frontend/`。后台接口新增需求写入 PR，不自行改后端或数据库。原有 API 字段先保持不变；新增三档方案界面待王天一的接口约定确认后接入。不要为了截图好看把 API 返回替换为固定成功数据。

保留“合成任务”“未评估”“费用未知”“待复核”等实际状态。可以优化文案，但不能把演示概率显示为真实疾病风险，把缺少规则显示为通过，或用前端数值代替后端计算。AI 说明目前是本地模板，不能改成声称已接入大模型。

开始改代码前阅读 `frontend/AGENTS.md` 和相应 Next.js 本地文档。

### 验收

- 实际走通演示案例加载、记录保存、方案生成、详情刷新回看、下载和说明提交。
- 桌面约 1440px 和窄屏约 390px 下无关键内容被遮挡，主要流程可操作。
- 至少展示有数据、无数据和请求错误三个状态；图表数值与接口一致。
- `npm test`、`npm run lint`、`npm run typecheck`、`npm run build` 通过。
- PR 附关键页面前后截图、操作步骤和仍未完成的交互。

## 王天一：价格、预算和三档方案

### 目标与顺序

把当前统一候选草稿扩展为有明确差异和可追溯计算的基础、标准、深入三档方案。档位首先表达项目组合与预算偏好，不直接宣称医学必要性。

1. 先提交短接口设计：候选项目、规则结果、费用信息、预算和档位的输入；项目选择、排除原因、费用汇总和不可满足原因的输出。与负责人确认后实现。
2. 新建独立方案构建模块（建议 `backend/app/services/plan_builder.py`），复用现有排序和规则输出，不重新训练模型。
3. 定义确定性的三档选取策略，记录策略版本和每项选取依据。不得把规则禁止项目重新加入更高档。无法形成差异时明确说明原因。
4. 实现费用管理：金额、币种、来源、适用机构或地区、生效日期、是否演示价。金额使用十进制定点表示或整数分，避免浮点累计误差。
5. 实现预算条件、已知费用小计、费用未知项目数量。存在未知价格时不能声称总价完整或保证不超预算。规则要求与预算冲突时返回冲突说明，不能静默删除应复核项目。
6. 价格和选取结果进入方案快照，之后价格调整不改变已保存方案。

### 修改范围与协作

拥有新建的方案服务、相关 schema、价格模块及其测试。涉及 `models/domain.py`、`schemas/domain.py`、迁移文件时先在 PR 写清变更，由负责人协调；迁移使用唯一编号。第一份 PR 不直接大改公共入口 `api/routes/workflow.py`。

沿用现有 `simplified/standard/deep` 枚举值，不自行创造不兼容值。接口变更优先新增字段，保留旧方案读取能力。与王宏锦不同时修改同一模型服务。

测试价格必须标为演示价。真实价格需记录可核验来源；不凭经验填写。不需要自行建立医学规则或咨询专家。

### 验收

- 相同输入得到相同方案；每档可解释，规则禁用项目不会因高分或预算被恢复。
- 覆盖预算不足、未知价格、目录为空、重复候选、无可选项目和价格更新后的快照稳定性。
- 已有工作流和旧方案仍可读取。数据库迁移在测试数据库验证，不上传本地数据库。
- 提交接口示例、策略说明、针对性测试和后端规范检查结果。

## 王宏锦：公开数据与模型制品

### 目标与顺序

让数据准备和模型使用可复现，并逐步替换工作流中的临时合成模型。既有离线程序已支持 Logistic、随机森林、LightGBM，不从头重复搭建训练框架。

1. 筛选 2—3 个无需个人申请、允许所需用途的数据候选。提交数据主页、许可或使用条款、下载方式、字段、标签、人数、时间信息和适配局限。尚未实际核验的数量标为未知。
2. 选择一个可获取候选，编写可重复执行的下载或读取及转换入口、字段映射和质量摘要；原始数据不进 Git。不能用未经核验的镜像绕过申请或授权条件。
3. 明确任务到底是当前异常分类还是未来事件预测。没有随访或可靠时间信息的横断面数据，只能支持相应分类验证，不能包装成纵向预测；不同队列不能随意按行拼成同一患者。
4. 复用 `backend/app/research/risk_baseline.py`，在数据和标签条件满足后运行已有基线，保留患者级划分、预处理、版本和报告。条件不足时交付审计及适配代码，不能填假审核信息绕过任务检查。
5. 在独立风险模型目录新增制品加载与预测适配器，遵循已有 `ml/interfaces.py` 和 `ml/contracts.py`。模型训练放在线下，正常请求只加载可信制品并推理。
6. 定义模型输入、必需字段、输出、适用范围和版本。制品缺失、特征不符或人群不适用时返回明确不可用状态，不回退为虚构概率。第一版允许用合成测试制品验证加载，但必须保留合成标签。

### 修改范围与协作

主要负责 `backend/app/research/`、新建的风险适配器、相应测试及数据说明。不要直接替换 `workflow_models.py`，也不改 `api/routes/workflow.py`，由负责人在评审契约后接入。

当前数据任务不要求把无关数据集训练出的模型直接用于中国体检人群，也不要求本轮完成 DeepFM 的真实交互训练。没有真实推荐标签时明确说明证据缺口。

### 验收

- 他人按文档可得到相同输入格式；记录来源、许可、版本、文件哈希和质量检查。
- 所有指标注明真实数据或合成数据、任务定义和验证方式，不将内部随机划分称作外部验证。
- 制品保存再加载的预测一致；测试缺少制品、缺少特征及不兼容版本等失败情况。
- 交付可运行入口和接口示例，不只交 notebook、截图或一个无法重建的权重文件。

## 分支与交付流程

各自在自己的电脑或独立克隆目录工作，不共用同一工作目录切换分支。由仓库所有者配置协作权限；没有写权限可使用个人 fork 发 PR。

首次克隆并创建个人任务分支（以下以陈子正为例，其他人替换分支名）：

```powershell
git clone https://github.com/MrJerry-git/InsightCheck.git
cd InsightCheck
git switch main
git pull --ff-only origin main
git switch -c feat/ui-polish
```

按 README 重建依赖。Git 作者身份使用本人姓名和邮箱；希望贡献关联 GitHub 账号时使用已验证邮箱或 GitHub noreply 邮箱，不复制其他成员身份。

完成一个可验收的小增量后，检查差异，选择本次修改的文件提交：

```powershell
git status
git diff
git add <本次修改的文件>
git diff --cached
git commit -m "Describe the completed change"
git push -u origin feat/ui-polish
```

`<本次修改的文件>` 是需要替换的占位内容。不要提交 `.env`、密钥、个人体检资料、数据库、虚拟环境、node_modules 或大体积原始数据。

在 GitHub 发往 `main` 的 Pull Request，由张家睿审查后合并。本文不表示已启用 GitHub 分支保护，也不表示已邀请成员。

开发期间同步主分支，先提交或妥善保存自己的改动，再执行：

```powershell
git fetch origin
git merge origin/main
```

出现冲突时理解双方改动再解决，不整文件覆盖。合并后重新执行相关验证。不向别人的分支推送，不强制推送共享分支。

## 协作节奏与完成标准

第一轮小交付：陈子正交两页可运行界面；王天一交方案契约与纯服务；王宏锦交数据审计及加载契约。三项互不等待。随后由负责人协调新增 API，陈子正再接入三档和模型状态界面。

公共文件 `backend/app/api/routes/workflow.py`、路由注册、全局配置和根 README 由负责人集中整合。前端归陈子正，避免其他成员同时美化相同组件。需要交叉修改时在 PR 明确说明并协调，不通过复制整份目录同步代码。

每个 PR 写明：解决的问题、修改范围、复现步骤、测试结果、截图或接口示例、已知限制。优先提交可运行的小 PR；不把三个人的分支一次性混合后再排错。

最终联合验收：新建或导入档案 → 查看历史和趋势 → 分析状态 → 三档候选与预算说明 → 规则追踪 → 保存 → 刷新回看 → 导出。合成、真实、未评估、未知费用等状态必须在整个流程中一致。
