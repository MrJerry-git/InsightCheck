# InsightCheck 开发路线

2026-09-16 更新：共同开发以 [实施设计](IMPLEMENTATION_DESIGN.md) 为准，以下是路线摘要。合作方数据尚未取得；按 [数据计划](DATASET_PLAN.md) 并行推进合成工程联调与公开数据审计，不等待合作方数据才开始开发。

目标是实现申报书中的个性化体检辅助推荐流程，并验证纵向病灶特征与风险输出的增量价值。iCan 作为阶段性实践，不单独改变研究目标。

## 继承的工程基础

已有数据模型及迁移、标准化、纵向指标特征、病灶匹配、PyTorch DeepFM、规则引擎和部分前端组件。这些实现与合成数据测试不能证明真实医学有效性。核心业务页面现已连接工作流接口，详见 [1.0 工程预览](V1_WORKFLOW.md)。

## 当前优先级（2026-09-17）

按用户确认，优先完成可操作的 1.0，不以需要申请的数据或专家咨询作为工程开发前置条件。先使用无需申请的公开数据及明确标注的合成案例联调，后续再用九华体检中心数据优化。下面的研究阶段与工程开发并行，NLST 未决条件只阻止该队列的真实实验，不阻止业务功能建设。

## 开发顺序与验收

| 阶段 | 工作 | 验收依据 |
| --- | --- | --- |
| 1 工程基线 | 从干净检出重建依赖，执行迁移和测试，统一演示与真实状态文案 | 环境说明、测试记录、启动结果 |
| 2 数据与标签 | 选择数据条件充分的异常方向，确认授权、字段、时间跨度、缺失和标签定义 | 数据字典、质量报告、受检者划分与时间验证方案 |
| 3 风险实验 | 实现 Logistic 回归、随机森林、LightGBM 和纵向特征消融 | 可复现训练入口、独立测试结果、误差分析 |
| 4 推荐实验 | 构建训练样本与负样本策略，对比基线、无风险 DeepFM 和完整 DeepFM | 排序指标、数据划分记录、级联误差分析 |
| 5 规则与方案 | 引入经核验规则，处理规则缺失和病灶匹配冲突，生成三档方案 | 规则来源与版本、违规率、边界测试 |
| 6 业务闭环 | 历史记录到风险、排序、规则、方案保存与界面展示 | 端到端演示、逐项证据与人工复核记录 |

先完成一个异常方向的完整流程，再扩展业务范围。AI 问答和可穿戴接口列为后续扩展。
