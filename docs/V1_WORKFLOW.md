# 1.0 工程预览：使用与验收

更新：2026-09-17。本轮目标是接通可操作的业务流程，支持共同迭代。研究任务、真实数据训练和专家审核不作为本轮工程交付前置条件；本版不代表已验证医学效果。

## 快速体验

1. 按根 README 安装依赖（后端包含 `.[dev,research]`），执行数据库迁移，再启动前后端。Windows 可使用根目录 `start-xunying.cmd`。
2. 打开 `http://127.0.0.1:3000/dashboard`，点击“创建 / 加载演示案例”。该操作幂等，不会重复创建同一案例。
3. 查看历年指标、影像文字和已有病灶轨迹，选择分析截止日期。
4. 点击“运行分析并保存方案”。首次运行会训练小型合成 LightGBM 和 DeepFM，耗时比后续请求长。
5. 查看候选项目、匹配分数、规则记录及模型状态。在历史列表回看，或进入独立详情；刷新页面后仍可查看已保存方案。
6. 点击“导出方案与证据”下载 JSON，包含当时输入历史、输出及规则执行记录。在“方案问题”输入风险、费用或数据来源问题，可获得本地结构化说明。

也可以创建匿名档案、录入日期及指标。手工记录默认不标记为合成；只有确为测试案例时才勾选合成数据。批量导入仍使用 `/health-records` 的校验、幂等导入流程，见 [导入说明](SYNTHETIC_IMPORT.md)。

## 本轮功能

| 环节 | 当前行为 |
| --- | --- |
| 档案 | 创建、选择受检者，查看记录数量 |
| 记录 | 手工录入字典内指标，校验重复指标、有限数值、字典边界及日期；批量导入复用已有模块 |
| 历史 | 按截止日期查看历年指标、影像文字、已有病灶轨迹 |
| 模型 | 合成案例运行真实 LightGBM 与 PyTorch DeepFM 代码，展示明确标注的演示结果 |
| 规则 | 对候选执行已有规则引擎，展示命中记录；未配置规则明确标记，不视为检查通过 |
| 方案 | 原子保存草稿与证据快照，同一请求编号重试复用，改变输入时拒绝冲突 |
| 回看 | 保存后独立详情、历史列表、JSON 导出、本地模板说明 |
| 管理 | 新增体检项目、新增缺失资料复核规则、规则启停、查看模型边界 |

## 数据和模型边界

合成模型版本为 `workflow-synthetic-v1`，只有所选截止日期内全部记录均为合成、年龄在 18—84 岁时才运行。真实或混合来源记录返回“未评估”，不套用演示概率。没有记录、日期不合法、项目目录为空时返回明确错误。

LightGBM 使用确定性生成的年龄和记录数量及人为标签；DeepFM 使用人为构造的匹配标签。二者用于接口和级联流程验证，不是疾病模型，也不构成推荐质量实验。当前工作流尚未把完整纵向指标、病灶特征接入正式风险制品。模型按项目目录缓存于进程内，服务重启后重建。

Synthea 属于合成数据，不等同于真实观察性队列。无需申请的公开数据继续筛选和审计；NLST 的队列定义未决条件不会被本版合成结果替代。九华数据取得后再补充人群适配和真实评估。

## 保存与接口

工作流入口为 `/api/v1/workflow`：`demo` 创建演示；`patients` 查询档案；`patients/{id}` 查询历史；`records` 录入；`plans` 生成及列举；`plans/{id}` 回看；`plans/{id}/export` 下载；`plans/{id}/explain` 解释。

复用 Recommendation、RecommendationItem 和 AIReport，无新增迁移。AIReport 的 content 保存 JSON 快照，提供方标记为 local-template。档案后续修改不会改变已保存快照；这是业务快照，不是防篡改审计存储。模型与规则版本、输入历史随快照保留。当前按体检日期截断，尚未验证历史时点的数据实际可获得时间。

## 验收与后续

本轮后端全套 141 项测试、前端 2 项测试以及类型、规范和生产构建检查通过。新增用例覆盖真实模型联调、保存重试、请求冲突、快照稳定、混合来源禁止合成推理、日期截断、保存失败回滚和录入校验；导出内容与保存快照一致。

浏览器已验证加载案例、生成保存、独立详情回看、新建匿名档案、手工指标保存及费用说明表单；已确认导出触发文件下载。修复了表单按钮未显式声明提交类型导致无法提交的问题，导出采用服务端附件响应。

下一步完善价格与三档方案、病灶人工复核交互、正式模型制品接入及更丰富的报告。当前解释采用本地模板，尚未连接大语言模型。所有方案是待复核草稿，没有医学上已确认的必要项目；项目费用未知，不生成虚构总价。尚无鉴权，只适用于本机开发体验。
